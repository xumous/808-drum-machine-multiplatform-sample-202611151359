三、启动命令（脱离当前 PowerShell，后台常驻）
--------------------------------------------------------------------
因为 Start-Process 直接调用 catalina.bat 的引号在 PowerShell 里不稳定，且 JDK 17 对
Tomcat 9 的反射需要 --add-opens，最终采用直接启动 Bootstrap：

$env:JAVA_HOME='C:\jdk17-tmp\jdk-17.0.21+9'
$tc="$root\tools\apache-tomcat-9.0.99"
$cp="$tc\bin\bootstrap.jar;$tc\bin\tomcat-juli.jar"
$javaArgs=@(
  '--add-opens=java.base/java.lang=ALL-UNNAMED',
  '--add-opens=java.base/java.io=ALL-UNNAMED',
  '--add-opens=java.base/java.util=ALL-UNNAMED',
  '--add-opens=java.base/java.util.concurrent=ALL-UNNAMED',
  '--add-opens=java.rmi/sun.rmi.transport=ALL-UNNAMED',
  "-Dcatalina.home=$tc",
  "-Dcatalina.base=$tc",
  "-Djava.io.tmpdir=$tc\temp",
  "-Djava.util.logging.config.file=$tc\conf\logging.properties",
  "-Djava.util.logging.manager=org.apache.juli.ClassLoaderLogManager",
  '-cp', $cp, 'org.apache.catalina.startup.Bootstrap', 'start')
Start-Process -FilePath "$jdk\bin\java.exe" -ArgumentList $javaArgs `
  -RedirectStandardOutput "$root\09_jsp\build\tomcat-out.log" `
  -RedirectStandardError  "$root\09_jsp\build\tomcat-err.log" -WindowStyle Hidden

八、过程中修掉的问题（均已在两版源码中修正）
--------------------------------------------------------------------
1) WAR 里 classes 放错位置：最初打包到 WAR 根，/app 与 /api/* 全部 404；
   改为 WEB-INF/classes 后恢复 200。
2) Tomcat 直接 java 启动缺少 --add-opens：JDK 17 下 JreCompat 初始化失败，
   补 5 个 --add-opens 参数后正常。
3) 10_javaee 把编码 Filter 映射到 /* 时，Tomcat DefaultServlet 对静态 JS 改用
   Writer 输出，UTF-8 的中文被按 GBK 二次编码（jsdom 里表现为乱码）；
   把 Filter 映射收窄到 /app 与 /api/* 后，服务端 JS 字节与源码 SHA 一致。
4) MIDI 头端序错误：复用引擎原来用 RIFF 的小端写 MThd/MTrk 长度，
   DAW 会把它读成 0x06000000。已在两版 XuEngine.exportMidi 中改为大端
   （os.writeInt/writeShort），当前 format=1、tracks=1、ppq=480、MTrk 长度正确。
5) JSON 带 UTF-8 BOM 时解析失败：在 Json.parse 入口剥离 U+FEFF，记事本工程可直接加载。
6) 首页工程 JSON 从 2.19 MB（带缩进）压缩到约 355 KB（字符串外去空白），
   页面加载明显变快。

九、仍未完成 / 已知限制（诚实说明）

   已用 jsdom 执 DOM/事件逻辑、用 Node 执行 worklet 的 DSP 代码做替代验证。

   若从其它机器用 http://<局域网IP>:18080 访问，Chrome 会拒绝 audioWorklet，
   此时需要 HTTPS 或本机访问。
3) 浏览器实时块为 128 帧，服务端导出沿用规格书的 Java 引擎 BLOCK=512。
   逐声部对照完全一致；整首混合的统计值有约 3% RMS、约 10% 峰值差异
   （Java 引擎以 128 帧渲染时峰值 0.337651 / RMS 0.117824，与 worklet 完全一致）。
   若要求“导出与浏览器逐样本相同”，需把导出 BLOCK 改为 128，或给 Java 引擎补块无关性修正。
4) 02_java_swing 原始副本的 exportMidi 仍保留旧的 LE 头写法；本次只修正了
   09_jsp / 10_javaee 两份 WAR 内的 XuEngine（避免越界改其它版本）。
5) 未接真实 MIDI 输入设备（规格第 8 节属于桌面版能力），Web 两版提供
   屏幕试听、音序播放与导出；MIDI 输入线程未实现。
6) 浏览器端未实现“分轨实时监听”，分轨只在服务端导出 WAV 时生效。
